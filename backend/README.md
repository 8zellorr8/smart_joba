# Backend этапа 1

Реализованы вход подготовленными аккаунтами, выход, серверные сессии, матрица
прав с областью доступа и проверка связи с PostgreSQL. Импорт и составление
расписания относятся к следующим этапам.

Все команды ниже выполняются из корня репозитория после подготовки `.env`
и отдельной локальной PostgreSQL. Секреты хранятся только локально.

```powershell
.venv/Scripts/python.exe -m pip install -r backend/requirements.lock.txt
.venv/Scripts/python.exe -m alembic -c backend/alembic.ini upgrade head
.venv/Scripts/python.exe -m backend.app.seed
.venv/Scripts/python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

Схема API: `GET /api/openapi.json`; Swagger UI с внешним CDN не используется.
`GET /api/auth/session` возвращает пользователя и CSRF-токен для заголовка
`X-CSRF-Token`; cookie CSRF недоступен JavaScript и связан с текущей сессией.
`POST` также требует точный разрешённый `Origin`. Ответы API имеют `no-store`.

Пароли демонстрационных аккаунтов случайные и записываются seed-командой в
`.local/accounts.json` и `.local/accounts.txt`; повтор не меняет аккаунты.
Эти файлы нельзя коммитить. Демообласть, группа и преподаватель обозначены как
синтетические и не представляют данные колледжа.

Сервер хранит только SHA-256 хеши криптографически случайных токенов сессии;
пароли — Argon2id. Текущие срок сессии 8 часов, окно ограничителя 15 минут и
порог 5 попыток на адрес аккаунта — **технические настройки этапа 1**, а не
подтверждённая политика колледжа. Дополнительный предел на IP — 50 попыток за
это окно. Параметры настраиваются окружением. Ограничитель резервирует попытку
под блокировкой строки PostgreSQL до проверки пароля, включая параллельные
запросы. Успешный вход обнуляет только счётчик данного аккаунта.

У администратора нет автоматического права утверждения или публикации.
`can_publish` выдаётся отдельно роли `approver` в конкретной области. Доступ
читателей ограничен подтверждённой связью преподавателя или группы.

`POST /api/schedule-versions/{id}/approve?scope_id={id}` — только проверяемая
граница доступа будущего модуля: составитель получает 403, утверждающий в
своей области — 501. Утверждение, проверка владения настоящей версией и
публикация ещё не реализованы; этот маршрут не сообщает об успехе.

Проверка тестов требует `TEST_DATABASE_URL`, указывающий на отдельную
loopback-БД с именем, заканчивающимся `_test`. Fixture очищает **только эту
проверенную БД**, основной `DATABASE_URL` для тестовых операций не используется.

```powershell
.venv/Scripts/python.exe -m pytest backend/tests -p no:cacheprovider -q
```

Покрыты AC-024a/b/c/d, AC-026d, граница AC-010a, CSRF, подмена области,
разделение полномочий администратора и утверждающего, истечение/отзыв сессии,
блокировка аккаунта, ротация токена, отсутствие секретов в ответах и аудите.
Полное выполнение AC-010a проверяется повторно после реализации версий.

Код разделён на чистую доменную матрицу (`domain`), сценарии входа
(`application`), хранение и криптографические адаптеры (`infrastructure`),
HTTP-контракты (`adapters`). Схему приложения создаёт Alembic, а не запуск API.
