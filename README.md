# Оқужол

**Оқужол** — локальный учебный портал для колледжа. Он связывает опубликованное расписание, электронный журнал, курсы и задания. Преподавателю проще отмечать посещаемость и проверять работы, студенту — находить занятия и видеть собственные результаты, сотрудникам — готовить и публиковать расписание. Интерфейс приложения — на казахском языке.

Этот README описывает код ветки [`codex/oqujol-brand`](https://github.com/8zellorr8/smart_joba/tree/codex/oqujol-brand). Имя репозитория `smart_joba` сохранено; название продукта — «Оқужол».

## Что реализовано

| Роль                   | Возможности                                                                                                                                                                                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Администратор          | Ведёт карточки студентов, состав групп, связи аккаунтов и назначения преподавателей для журналов. Может загрузить список студентов из текста, TXT, CSV или одноколоночного XLSX с проверкой совпадений перед сохранением.                                                                                                |
| Составитель расписания | Загружает книгу нагрузки S1 в XLSX, проверяет строки, задаёт календарь и часы, составляет расписание вручную или запускает генератор, затем проверяет конфликты и отправляет версию на согласование.                                                                                                                     |
| Утверждающий           | Рассматривает версию расписания, возвращает её на исправление или одобряет. Публикация доступна только при отдельном праве в рабочей области.                                                                                                                                                                            |
| Преподаватель          | Видит свои занятия и журналы, записывает тему, посещаемость и оценки 0–100, исправляет записи с причиной. Открывает курс, добавляет темы по неделям 1–10, текстовые и PDF-материалы, задания; проверяет ответы и возвращает их на доработку. На главной есть очередь непроверенных ответов и незаполненной посещаемости. |
| Студент                | Видит опубликованное расписание на семь дней, доступные курсы и задания, отправляет ответы текстом или PDF. В личном кабинете смотрит собственные оценки и посещаемость, включая результаты из прежней группы.                                                                                                           |

Общие возможности: поиск по доступным предметам и курсам, просмотр истории исправлений журнала, версии условий заданий, выгрузка опубликованного расписания в XLSX. Сервер проверяет роль, рабочую область и подтверждённую связь с группой или преподавателем. Курсы и ответы доступны только преподавателю и студенту; отсутствие оценки отличается от оценки `0`.

## Как работает решение

1. Составитель загружает и проверяет исходную нагрузку S1, задаёт учебный календарь и создаёт проект расписания. Генератор использует OR-Tools CP-SAT; результат дополнительно проверяет независимый валидатор.
2. Утверждающий рассматривает версию. После одобрения и отдельной проверки готовности расписание публикуется. Студенты и преподаватели видят только разрешённые им занятия из действующей публикации.
3. Администратор подтверждает студентов, состав групп и назначения преподавателей. Преподаватель открывает занятие из опубликованного события и заполняет журнал.
4. Преподаватель ведёт курс и задания по подтверждённому журналу. Студент читает материалы, сдаёт работу и видит результат проверки вместе с комментарием.

Установка создаёт только синтетическую рабочую область, одну группу, одного преподавателя и пять аккаунтов. **Готовые занятия, оценки и курсы не создаются автоматически.** Для полного сценария нужны подтверждённые исходные данные либо отдельно подготовленный синтетический пример.

## Технологии

| Компонент          | Технологии из репозитория                                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| Интерфейс          | React, TypeScript, Vite; Vitest и Testing Library для тестов. Локальные шрифт Inter и значки Phosphor.                         |
| Сервер и API       | Python, FastAPI, Pydantic; собственный HTTP API для интерфейса.                                                                |
| Данные             | PostgreSQL, SQLAlchemy, Alembic; пароли защищены Argon2id.                                                                     |
| Расписание и файлы | OR-Tools CP-SAT; openpyxl и defusedxml для XLSX на сервере, read-excel-file для локального чтения списка студентов в браузере. |
| Проверки           | pytest, Vitest; браузерные сценарии в `frontend/e2e/` используют установленный отдельно Playwright.                            |

AI-модели проект не вызывает. Генератор расписания — алгоритм ограничений, а не AI-сервис. Во время работы портала внешние облачные API не требуются; интернет нужен при первой установке зависимостей.

## Архитектура

- `frontend/src/` — страницы пяти ролей, формы и запросы к API. Собранные файлы интерфейса отдаёт тот же локальный сервер.
- `backend/app/adapters/` — HTTP-маршруты и проверка входных данных; `application/` — сценарии расписания, журнала, курсов и заданий; `domain/` — правила и права; `infrastructure/` — модели и работа с PostgreSQL.
- `backend/app/worker.py` — отдельный локальный процесс для задач генератора расписания. Он получает задания из базы и запускает ограниченный по ресурсам расчёт.
- `backend/migrations/` — версии схемы БД; `scripts/run.ps1` и `scripts/dev.py` — установка, запуск и тестирование на Windows.

Поток данных: **браузер → FastAPI → правила приложения → PostgreSQL**. Генератор работает через отдельный worker; клиент не получает права доступа из собственных параметров запроса.

## Установка и запуск

Нужны **Windows с PowerShell**, Python **3.12+**, Node.js **от 24.15 до 26** с npm, бинарные файлы PostgreSQL **18** и .NET Framework **4.x** для локального запуска PostgreSQL. Понадобится интернет при первой установке Python- и npm-зависимостей. Автоматический скрипт запуска рассчитан на Windows.

1. Склонируйте ветку с описанной здесь версией проекта и откройте её папку:

   ```powershell
   git clone --branch codex/oqujol-brand --single-branch https://github.com/8zellorr8/smart_joba.git
   cd smart_joba
   ```

2. Подготовьте отдельную локальную БД, зависимости, миграции, демоаккаунты и сборку интерфейса:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 setup
   ```

   Скрипт создаёт `.env` и базу проекта на `127.0.0.1:55432`. Он не использует существующую базу PostgreSQL. Если PostgreSQL установлен нестандартно, перед `setup` задайте путь к его папке `bin` через переменную `SMART_JOBA_PG_BIN`.

3. Запустите API, worker и локальную БД:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 start
   ```

4. Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/). Логины и случайно созданные пароли пяти демоаккаунтов находятся только на вашем компьютере в `.local/accounts.txt`. Не публикуйте этот файл.

Состояние и остановка:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 status
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 stop
```

## Как проверить решение

1. После `setup` откройте `.local/accounts.txt` и войдите по очереди как `admin`, `scheduler`, `approver`, `teacher` и `student`. Убедитесь, что меню и доступные разделы меняются с ролью. Подготовленные аккаунты используют только синтетические названия.
2. Под `teacher` откройте «Курстар» и «Журналдар», под `student` — «Оқу профилім». На чистой установке курс и журнал пусты, а личные результаты не выдаются без подтверждённой карточки студента: исходное расписание и состав ещё не созданы.
3. Запустите автоматическую проверку на отдельной тестовой БД. Тесты создают собственные синтетические записи и проходят сценарии публикации, журнала, курсов, заданий и прав доступа:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 test -SkipInstall
   ```

Скрипт запускает backend-тесты, frontend-тесты, проверку TypeScript и production-сборку. Браузерные сценарии требуют отдельно установленный Playwright и Chromium; они не входят в эту команду.

## Данные и интеграции

- Исходная нагрузка S1 загружается как XLSX, проходит предпросмотр и проверку перед применением. Подлинные книги колледжа в публичный репозиторий не включены.
- Списки студентов можно вставить текстом либо прочитать из одноколоночных TXT/CSV/XLSX. Выбранный файл состава разбирается в браузере; на сервер отправляется подтверждённый список и явное решение по совпадениям имён.
- Материалы и ответы курсов хранятся как текст или PDF в пределах разрешённого курса. Опубликованное расписание можно выгрузить в XLSX с текущими фильтрами.
- Данные, сессии и история хранятся в локальном PostgreSQL. Пароли демоаккаунтов, `.env`, локальная база и загруженные исходники остаются в игнорируемой Git папке `.local/` или других локальных путях.
- Интеграции с облачными LMS, внешними календарями и AI-сервисами в коде нет. Занятость ресурсов вне этого проекта требуется подтверждать отдельно.

## Ограничения текущей версии

- После установки есть демоаккаунты, но нет готового учебного набора. Для показа полной цепочки нужно загрузить разрешённые исходники и подтвердить связи либо создать отдельный синтетический пример.
- Курсы доступны только преподавателю с действующим назначением и студенту с подтверждённой связью. Администратор настраивает связи, но не читает материалы и ответы.
- Задания не формируют автоматически итоговую оценку по предмету; баллы журнала и заданий хранятся отдельно.
- Текст материала или ответа ограничен 20 000 символами, PDF — 5 МБ. Пакетная загрузка состава поддерживает один столбец и до 200 студентов за раз.
- Для `scripts/run.ps1` реализовано управление процессами Windows. Запуск на другой ОС и работа на другой машине не подтверждены этим README.
