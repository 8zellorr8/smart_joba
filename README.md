# Smart Joba

Локальный сайт планирования расписания колледжа по [ТЗ v0.9](docs/spec/v0.9/college_timetable_spec_v0_9_ru.docx). Готовы локальная основа, пять ролей, серверные права, казахский интерфейс, импорт S1 с предпросмотром и историей, календарь и расчёт часов, редактор, генератор CP-SAT, независимый валидатор, версии, согласование, атомарная публикация и закрытый читательский просмотр.

Для следующего расширения подготовлено [ТЗ электронного журнала v1.0](docs/spec/v1.0/college_ejournal_spec_v1_0_ru.docx): оценки 0–100, посещаемость, темы занятий и кабинет студента с сохранением расписания и пяти ролей. В документе 48 новых требований, 64 критерия приёмки и план на одну неделю. [Реестр для ИИ-агентов](docs/spec/v1.0/college_ejournal_spec_v1_0_requirements.json) содержит ID, связи требований и AC, предположения и наследование v0.9. Это постановка задачи; журнал пока не реализован, код и БД текущего сайта не изменены.

Следующий отдельный этап MVP — XLSX. Регистрация и восстановление пароля остаются во второй очереди.

Первый пакет UI/UX-улучшений объединяет шрифты, заголовки, поля, кнопки, карточки,
таблицы и текстовые статусы. Шрифт Inter включён в локальную сборку; права и
рабочие сценарии сохранены. Подробности проверок — в
[отчёте UI/UX](docs/implementation/ui-polish-first-package-test-report.md).

Главный экран и недельное расписание используют выбранный вариант 2: повестка
дня, карточка проекта, недельная сетка и сведения о занятии. Неделя и прежний
список переключаются с сохранением фильтра; редактирование доступно по прежним
правам. Подробнее: [оформление](docs/design/agenda-weekly/README.md),
[проверки](docs/implementation/agenda-weekly-test-report.md),
[визуальная сверка](design-qa.md).

## Запуск в Windows

Нужны Python 3.12+, Node.js 24.15+ с npm, установленные бинарники PostgreSQL 18 и .NET Framework 4.x из Windows. Сначала откройте PowerShell в папке этого репозитория.

Первичная подготовка требует интернета для установки зависимостей:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 setup
```

Обычный запуск после подготовки работает без интернета:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 start
```

Откройте **http://127.0.0.1:8000**. Подготовленные логины и случайные пароли находятся только на этом компьютере в **`.local/accounts.txt`**. Это синтетические демоаккаунты, а не сведения колледжа. Роли: `admin`, `scheduler`, `approver`, `teacher`, `student`; пароли для каждой роли разные. При повторном `setup` существующие пароли и назначения сохраняются.

Остановка, состояние и проверки:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 status
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 test
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 stop
```

Скрипт создаёт отдельный кластер в `.local/postgres/data` на `127.0.0.1:55432`, базы `smart_joba` и `smart_joba_test`. Существующие службы и базы PostgreSQL не меняются. Если бинарники установлены в другом месте, задайте `SMART_JOBA_PG_BIN` с путём к их папке `bin`. Порт 8000 занят другим приложением — запуск остановится с сообщением, чужой процесс останется работать.

`setup` использует управляемую локальную `.env`; при несовпадении её адресов БД с настройками проекта миграции и seed останавливаются. Не заменяйте её параметрами рабочей базы колледжа. Журналы диагностики находятся в `.local/`. Не отправляйте `.env`, `.local/`, дампы и файлы с паролями в GitHub.

## Импорт S1

1. Войдите под `scheduler` и откройте «Деректерді импорттау».
2. Выберите XLSX, учебный год, вид данных, лист и последнюю строку таблицы. По умолчанию: `Жүктеме!A1:L237`, шаблон `s1-v1`. Год задаётся пользователем; из имени файла он не определяется.
3. Укажите подтверждённую единицу нагрузки либо оставьте её неуточнённой: значения сохранятся с вопросом, без преобразования семестровых часов в недельные.
4. Посмотрите новые, изменённые и исчезнувшие записи. Нажмите координату строки для проверки исходных значений и отдельных вопросов.
5. При наличии основания исправьте значения, подтвердите значение пустой подгруппы и соответствия справочников. Исправление одного поля не закрывает остальные вопросы.
6. Подтвердите применение **всей партии**, включая страницы, которые сейчас не показаны. Повторное применение не создаёт дубликатов; исчезнувшие записи автоматически не удаляются.

Неразрешённые строки сохраняются как вопросы. Несколько преподавателей и повторяющиеся ключи не создают независимые потребности или фиктивные назначения. Преподаватель назначается только для полностью проверенной строки. История доступна при проверке строки; исходная книга хранится неизменной в локальной БД и выдаётся через закрытый API.

`admin` может смотреть партии и исходную книгу, а применять их может `scheduler` в своей области. Студенты, преподаватели и утверждающий не имеют доступа к исходным книгам. Синтетические данные и сведения колледжа разделены контекстом.

Пределы XLSX и правила сопоставления описаны в [контракте S1](docs/implementation/stage-2-s1-contract.md), результаты — в [отчёте импорта](docs/implementation/stage-2-s1-test-report.md).

## Календарь и часы

1. Войдите под `admin` и откройте «Оқу күнтізбесі». Создайте календарь группы, задайте год и тип данных.
2. Введите явные границы, периоды теории/практики/каникул/аттестаций и номера семестров. Неизвестные даты остаются запрещёнными для обычного занятия. Исключение на одну дату требует основания.
3. Настройте время занятий, минуты академического часа и пары, учебный часовой пояс. 45/90 и Asia/Almaty пока **предположения**; календарь, единицы и пояс подтверждаются отдельно с источниками.
4. Сохраните календарь и проверьте конкретный диапазон дат. Границы вторник–понедельник сохраняются.
5. В расчёте выберите диапазон, время и дни недели. Отменённые даты не добавляют часы: десять занятий по 90 минут при норме 45 дают 20 академических часов, после одной отмены — 18.
6. Для остатка выберите подтверждённую семестровую потребность S1 той же группы и контекста. Неизвестные единицы или связь с семестром оставляют остаток неизвестным. Сравнивать разные семестры нельзя.

Составитель и утверждающий читают календарь и считают часы; изменяет настройки только администратор. Это предварительный расчёт: занятия расписания и факт проведения не создаются. Старые правки отклоняются, история ревизий сохраняется.

После обновления кода примените миграции без переустановки зависимостей и перезапустите сервер:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 setup -SkipInstall
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 stop
powershell -ExecutionPolicy Bypass -File .\scripts\run.ps1 start
```

Контракт: [календарь и часы](docs/implementation/stage-3-calendar-contract.md). Проверки: [отчёт этапа 3](docs/implementation/stage-3-calendar-test-report.md).

## Редактор расписания

1. Администратор подтверждает календарь и готовит кабинеты в «Кабинеттер». Для исключительности кабинета нужно явное основание; неизвестные свойства сохраняют вопрос.
2. Составитель (`scheduler`) открывает «Кесте редакторы» и создаёт именованный черновик контекста S1. При отсутствии подтверждённых назначений сначала нужно решить вопросы импорта.
3. «Сабақтар қосу» создаёт повторение из подтверждённого назначения, кабинета и времени из календарной сетки. Задаются диапазон и дни недели либо конкретные даты.
4. «Бір күнді өңдеу» меняет одно проведение, включая перенос, отмену и закрепление. «Барлық қайталануды өңдеу» явно заменяет весь набор, включая индивидуальные исправления; закреплённые изменения не сбрасываются молча.
5. Таблица поддерживает группу, преподавателя, кабинет, даты и страницы. Отчёт показывает оба конфликтующих занятия и точную дату; интервалы, соприкасающиеся концом и началом, не пересекаются.
6. Черновик с конфликтами сохраняется для исправления. Календарный запрет отклоняет размещение; ошибка не очищает форму. Старые ревизии получают 409.

Утверждающий (`approver`) читает черновик без права редактирования. Администратор не получает права составителя автоматически. Преподаватели и студенты не видят неопубликованные черновики.

Краткая проверка редактора относится к текущему черновику; полную независимую проверку выполняет отдельный раздел, включая подтверждённые условия. Согласование и публикация описаны ниже. План не регистрирует фактически проведённые занятия.

Контракт: [редактор и конфликты](docs/implementation/stage-4-editor-contract.md). Результаты: [отчёт этапа 4](docs/implementation/stage-4-editor-test-report.md).

## Устройство проекта

| Каталог | Назначение |
|---|---|
| `backend/app/domain` | Права, импорт, календарь, часы и поиск конфликтов без HTTP и SQL |
| `backend/app/application` | Вход, импорт, календарь, черновики, ресурсные ссылки и аудит |
| `backend/app/infrastructure` | SQLAlchemy, Argon2id, подписи CSRF |
| `backend/app/adapters` | HTTP API, безопасные ошибки, DTO |
| `backend/migrations` | Версионируемая схема PostgreSQL |
| `frontend/src` | React + TypeScript, KK-ресурсы, адаптивные экраны |
| `scripts` | Изолированная локальная подготовка, запуск и остановка |

Пароли хешируются Argon2id. БД хранит хеши непрозрачных серверных сессий; браузер получает HttpOnly/SameSite cookie. Проверки прав выполняются на сервере при каждом закрытом запросе. Администратор не получает автоматического права утверждать и публиковать. HTTP разрешён только для локального запуска; сетевое развёртывание в этот этап не входит.

API и интерфейс обслуживаются одним процессом. Во время разработки отдельно доступны `npm run dev` в `frontend` (порт 5173, прокси `/api` на 8000) и uvicorn; подробности — в [backend/README.md](backend/README.md) и [frontend/README.md](frontend/README.md). Схема API: `/api/openapi.json`, работоспособность БД: `/api/health`.

## Генератор и независимый валидатор

После обновления исходников выполните `setup` для установки зафиксированных OR-Tools/psutil, миграции и сборки. Существующие аккаунты и пароли сохраняются. Обычный `start` запускает API и отдельного работника; повторный запуск не создаёт второго работника. Для обновления уже работающих процессов используйте `stop`, затем `setup` и `start` (когда тесты не выполняются).

1. Под `admin` откройте «Есептеу шарттары», выберите контекст и введите подтверждённые размеры групп, свойства кабинетов, требования предметов и доступность преподавателей/кабинетов. Укажите основание и подтвердите данные. Неизвестное оставляйте неизвестным: оно блокирует расчёт.
2. Под `scheduler` откройте «Автоматты құрастыру және тексеру». Выберите год/вид данных, группы, кабинеты и семестр. При необходимости выберите исходный черновик для сохранения его закреплённых занятий.
3. Нажмите «Дайындығын тексеру». Неразрешённые строки S1 и обязательные вопросы показываются до запуска.
4. Нажмите «Есептеуді бастау». Отдельный процесс ищет полное допустимое размещение; экран показывает фактические этап, время и результат. Задание можно отменить, его ID восстанавливается после обновления страницы.
5. При успехе откройте **новый** черновик кнопкой «Жобаны редакторда ашу». Исходный черновик не меняется. «Допустимый» означает соблюдение подтверждённых правил выбранного профиля; оптимизация удобства не включена.
6. Для отдельной проверки выберите черновик в «Тексерілетін жоба» и нажмите «Жобаны тексеру». Отчёт относится к показанной ревизии и выбранным группам/семестру. Изменение данных помечает старый результат/отчёт устаревшим.

Встроенная проверка редактора остаётся краткой диагностикой его событий. Полный для поддержанного профиля независимый отчёт открывается в разделе генератора/проверки. Непроверенная занятость других отделений видна отдельно. Тестовые условия локального примера синтетические; реальные календарь, доступность и свойства помещений автоматически не подтверждаются.

Подготовленный пример отображается с понятными KK-названиями: «Демо топ 101-А/101-Б», «Демо оқытушы А/Б», «Ағылшын тілі · демо», «Қазақ тілі · демо», «Информатика · демо» и «Демо кабинет 101/102». Единый словарь `frontend/src/demo-labels.ts` применяется только к известным демонстрационным подписям при `data_kind=synthetic`; произвольные названия и данные колледжа сохраняются. Понятная подпись файла показана вместе с исходным именем; поля сверки источника и скачиваемый XLSX остаются оригинальными. Отображение не меняет БД, ID, ревизии или сохранённые результаты проверок.

`approver` читает задачи/отчёты и запускает проверку черновика, но не генерацию и отмену. `admin` редактирует условия без доступа к черновикам через этот экран. Преподаватель и студент доступа к расчётам не получают.

Контракт, модель, права и лимиты: [этап 5](docs/implementation/stage-5-planning-contract.md). Испытания: [отчёт](docs/implementation/stage-5-planning-test-report.md), [карта AC](docs/implementation/stage-5-planning-acceptance.json). Воспроизводимый синтетический замер без БД: `.\.venv\Scripts\python.exe -m scripts.benchmark_planning`.

## Версии, согласование и опубликованный просмотр

После обновления выполните `setup`, чтобы применить `0006_publication` и собрать интерфейс; работающие процессы обновляйте через `stop` / `setup` / `start`, когда проверки не выполняются. Перед миграцией сохраните локальную резервную копию. Аккаунты, пароли и исходники сохраняются.

1. Под `scheduler` откройте готовый черновик в редакторе и нажмите «Нұсқалар, келісу және жариялау»: откроется именно выбранная версия. В разделе «Келісу және жариялау» проверьте номер, группы, кабинеты и семестр, затем «Келісуге жіберу».
2. Под другим аккаунтом `approver` просмотрите содержимое и независимый отчёт. «Себебімен қайтару» требует причины; составитель затем использует «Жобаны түзетуге ашу». «Нақты редакцияны бекіту» утверждает показанную редакцию; автор своего содержимого этого сделать не может.
3. При отдельном праве публикации нажмите «Жариялауға дайындығын тексеру», затем «Тексеріп, жариялау». Сервер заново проверяет входы, часы и общую занятость. При потере связи кнопка повтора использует ту же операцию.
4. «Жарияланған кесте» показывает текущую разрешённую публикацию: номер, дату, область, занятия и фильтры. Преподаватель получает свои занятия, студент — свою подтверждённую группу. Исходники и комментарии им не передаются.
5. Для исправления опубликованного содержимого составитель создаёт «Жаңа нұсқаны жасау». Прежняя публикация действует до утверждения и успешной публикации новой; затем её версия переходит в архив, а снимок сохраняется.

Подготовленные ссылки читателей в тестовой среде должны указывать на синтетические справочники демонстрации; совпадение имени или кода не назначает доступ. Реальные данные колледжа требуют собственных подтверждений.

Контракт и рабочие предположения: [этап 6](docs/implementation/stage-6-publication-contract.md); результаты: [испытания](docs/implementation/stage-6-publication-test-report.md), [карта AC](docs/implementation/stage-6-publication-acceptance.json). Индекс общей занятости измеряется без БД: `.\.venv\Scripts\python.exe -m scripts.benchmark_publication`.
