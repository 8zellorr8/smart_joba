## Правила LMS

- Для расписания действует ТЗ v0.9, для электронного журнала — v1.0. Подробные контракты, карты критериев, ограничения испытаний и оба ТЗ доступны в [архиве](https://github.com/8zellorr8/smart_joba/tree/a6c2f6ce83d7f210370f234459b078f770852388/docs).
- Сохранять пять ролей и проверять текущую роль, область доступа и подтверждённую связь на сервере. Названия предметов и групп служат для отображения. При смене аккаунта, области или связи сбрасывать страницы клиента, при 401/403 очищать закрытые данные.
- Нагрузку S1 применять после подтверждения. Проверять точную ревизию расписания независимым валидатором. Согласование и публикацию выполнять по контракту версий. Писатели `publication_heads` берут эксклюзивную блокировку публикации до Scope. Исправления публикации оформлять новой версией.
- Для справочников журнала соблюдать порядок блокировок Scope → User/AuthSession/RoleGrant → JournalRegistry → связи. Для записи занятия сначала брать shared advisory publication lock, затем Scope, права, каталог и факт. Текущие объектные права проверять до квитанции повтора, квитанцию — до ревизии.
- Первую запись занятия привязывать к точному опубликованному событию и фиксировать снимок состава. Тему, посещаемость, оценки и историю сохранять в одной транзакции. Исправления требуют причины. Администратор управляет составом без доступа к содержимому журнала.
- Оценка — целое число 0–100 или NULL. Пустой или отсутствующий массив grades исключать из отпечатка команды для совместимости с прежними квитанциями. Непустой массив включать. Ограничение записи — 100 различных затронутых студентов суммарно.
- Кабинет студента использует привязанный на сервере student_id и снимок состава на дату занятия, включая прежние группы. Выдавать только собственные результаты в разрешённой области и data_kind. Чтение использует блокировку Scope, страницы выдачи — одну ревизию.
- Сохранять казахский интерфейс и общие компоненты заголовков и статусов. Предметы и недельное расписание читать постранично из доступных публикаций одной ревизии. Для перехода к неделе передавать точный ID публикации и дату.
