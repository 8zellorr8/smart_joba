# Первый этап локального приложения

Основание: ТЗ v0.9, REQ-005/006, AUTH-003 и применимые AUTH-007/008, NFR-001/002/006, LOC-001–003. Пользователь разрешил реализацию первого этапа 21.10.2026.

## Границы

Реализуются локальный запуск, PostgreSQL и миграции, подготовленные аккаунты пяти ролей, вход и выход, серверные сессии и проверка области доступа, казахский интерфейс. Данные помечаются как демонстрационные. Реальные материалы колледжа не загружаются.

Регистрация, восстановление, импорт, календарь, редактор, генератор и публикация здесь не реализуются. Права будущих действий задаются серверным каталогом; недоступное действие не показывает фиктивный успешный результат.

## Контракты

- `GET /api/health`: `{status: "ok", database: "ok", stage: 1}` после фактической проверки БД.
- `GET /api/auth/session`: `{user: null | User, csrf_token: string}`; ответ не кешируется, CSRF хранится клиентом только в памяти.
- `POST /api/auth/login`: JSON `{email, password}`, заголовок `X-CSRF-Token`; ответ — тот же объект сессии. Неизвестный аккаунт и неверный пароль дают одинаковый публичный отказ.
- `POST /api/auth/logout`: заголовок `X-CSRF-Token`; `204`, сессия отзывается сервером.
- `GET /api/me`: разрешённый профиль либо `401`.
- `GET /api/scopes/{scope_id}/workspace`: `{scope: {id, name, is_demo}, role_codes: string[], permissions: string[], stage: 1}`; чужая область не раскрывается.
- `User`: `{id, email, display_name, home_scope_id, grants: [{role, scope_id, scope_name, is_demo, group_id, teacher_id}]}`; поля связей допускают `null` по роли.
- Ошибка: `{error: {code, params, request_id}}`; пароль, cookie, CSRF и исходное тело запроса в неё не включаются.

Коды ролей: `admin`, `scheduler`, `approver`, `teacher`, `student`. Авторизация использует назначение роли в запрошенной области из БД. Роль администратора не предоставляет утверждение и публикацию. Право публикации задаётся отдельно.

## Локальная среда

Интерфейс: React/TypeScript/Vite. API: FastAPI. БД: PostgreSQL, SQLAlchemy и Alembic. Готовый интерфейс обслуживается API с одного origin `http://127.0.0.1:8000`; dev-сервер Vite на `127.0.0.1:5173` проксирует `/api`.

Для разработки создаётся отдельный кластер PostgreSQL на `127.0.0.1:55432` внутри игнорируемого `.local`. Существующий системный кластер не меняется. Рабочая и тестовая БД разделены; тесты не очищают рабочую БД. Приложение подключается отдельной ролью без прав суперпользователя.

Переменные: `DATABASE_URL`, `TEST_DATABASE_URL`, `APP_SECRET`, `LOCAL_ONLY=true`, `COOKIE_SECURE=false`, `ALLOWED_ORIGINS=http://127.0.0.1:8000,http://127.0.0.1:5173`. Локальный HTTP допускается только для loopback по ADR ТЗ. Сессии используют HttpOnly/SameSite и CSRF; секреты не попадают в репозиторий и клиентский код.

## Приёмка первого этапа

Проверяются вход подготовленных аккаунтов, нейтральная ошибка, серверный выход, ограничение попыток, отсутствие секретов в ответах и аудите, матрица роли и области, CSRF и сохранение email при очистке пароля в форме. Полные AC утверждения, исходных файлов и изменения расписания остаются интеграционными до появления этих функций. Отчёт отличает выполненные проверки каркаса от приёмки всего MVP.
