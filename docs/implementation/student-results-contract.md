# J1.4: собственные результаты студента

Дата: 04.11.2026. Основа: ТЗ v1.0, JRN-STU-001–004, JRN-SEC-001/002, JRN-UX-001/003 и AC-JRN-035–041. Предыдущие контракты J1.1–J1.3 сохраняются; ID постановки не меняются.

## Пользовательский путь

Студент открывает «Оқу профилім» → «Менің нәтижелерім». Карточка сохранённого занятия показывает исходные дату, время и учебный пояс, предмет, группу, учебный год/семестр, тему, собственную оценку и посещаемость. NULL показан как «Бағаланбаған», ноль — как 0. Посещаемость независима от оценки. Для исключённой из состава строки есть текст о сохранённой прежней записи.

Фильтры: учебный контекст/семестр и предмет; возможен выбор всех периодов и предметов. Варианты формируются только из собственных сохранённых занятий. По 20 карточек на страницу, новые даты первыми; при равных датах порядок задают время и постоянный ID занятия. Смена фильтра возвращает первую страницу. Переходы «Алдыңғы бет»/«Келесі бет» сохраняют фильтры. Группы и профиль остаются в раскрываемом блоке. Кнопка расписания открывает существующий закрытый недельный просмотр; прежняя группа результата не подменяет разрешённую группу расписания.

Это чтение фактов. Средний балл, итоговая оценка, задания, курсы и XLSX в этот этап не входят. Допущения целочисленности и одной текущей оценки из QJ-001/QJ-006 не изменяются. Источник S1 автоматически не подтверждается.

## API

`GET /api/scopes/{scope_id}/journal/me/results`

| Параметр | Правило |
| --- | --- |
| `context_id`, `semester` | Оба отсутствуют либо оба присутствуют; UUID и номер 1–20. |
| `subject_id` | UUID из собственных доступных предметов; отсутствие — все. |
| `page` | Целое 1–1000000, по умолчанию 1. |
| `page_size` | Целое 1–100, по умолчанию 20; интерфейс использует 20. |
| `revision` | 64 шестнадцатеричных символа из предыдущего ответа; обязателен для страницы после первой. |

Неизвестные параметры, включая `student_id`, и повторные ключи отклоняются с 422. Чужой период/предмет — 403. За пределами последней страницы — 422. Ошибочный запрос не возвращает строки.

Ответ: собственные `student` и `memberships`, допустимые `periods`/`subjects`, `revision`, `page`, `has_next`, `items`. Поля элемента явно перечислены в `StudentResultsService`: ID/ревизия факта, дата/начало/конец/пояс, подписи предмета/группы/года/семестра, тема, собственные grade/attendance/active. Полные DTO занятия, другие студенты, их ID, снимки состава, основания, авторы и служебная история в ответ не включаются. `/journal/me` сохраняет совместимость.

## Права и целостность

1. Каждый запрос использует действующую сессию, `journal.read.self` в указанной области и подтверждённую связь аккаунта с одним `student_id`.
2. Общая читающая блокировка Scope и прежние проверки User/AuthSession/RoleGrant действуют до конца транзакции; писатели каталога и фактов используют прежний порядок блокировок. Кабинет не читает указатель текущей публикации и не берёт публикационную блокировку.
3. SQL выбирает только строки этого студента в контексте, группе и предмете той же области и `data_kind`; сохранённая принадлежность должна совпадать с источником и включать дату занятия.
4. Текущая группа аккаунта и текущие интервалы справочника не заменяют неизменяемый снимок принадлежности. Поэтому исправление справочника, перевод, `active=false` и новая публикация сохраняют доступ к собственному прежнему факту.
5. Данные публикации и журнала не изменяются; нового write API, миграции и новых таблиц нет. Схема остаётся `0009_journal_grades`.

Ревизия выдачи — SHA-256 от области, связанного студента, ревизии каталога, фильтров, размера страницы и отобранных собственных фактов с их ревизиями/значениями. Изменение набора или контекста чтения между страницами возвращает `409 JOURNAL_RESULTS_STALE`, без смешивания страниц разных состояний. Это маркер актуальности, не средство авторизации: права проверяются отдельно при каждом запросе. Текущая реализация загружает собственный набор для вычисления маркера и вариантов фильтров; ответ ограничен размером страницы. Проверка большой промышленной нагрузки остаётся вне текущих испытаний.

## Состояния интерфейса

Загрузка, успешное отсутствие записей, NULL, ошибка сети и запрет доступа различаются текстом. Пока загружается новая страница, старые карточки убираются. При сети сохраняются выбранные фильтры и возможность повторить тот же запрос; при stale предлагается первая страница с теми же фильтрами. При 401/403 стираются строки, профиль и варианты фильтров; 401 вызывает повторный вход. Повтор после отказа начинает запрос без прежних фильтров, чтобы смена привязки не оставляла пользователя на недоступном предмете. Старый запоздавший ответ игнорируется. Родительская оболочка сбрасывается при смене пользователя/области/подтверждённой связи.

Поля имеют явные label/id; смена страницы переводит фокус на заголовок результатов. На телефоне данные занятия и собственные показатели расположены вертикально. Даты используют локальный KK-словарь приложения и не зависят от наличия казахской ICU-локали браузера.
