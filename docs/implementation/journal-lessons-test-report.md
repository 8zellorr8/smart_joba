## Серверные сценарии

`backend/tests/test_journal_lessons.py` выполняет реальный путь импорта/календаря/генератора/публикации на синтетических данных перед созданием факта.

- Предпросмотр не создаёт запись; первое сохранение фиксирует ID, источник, состав, тему и пустые значения непереданных строк.
- Изменение текущего членства после записи не меняет исторический состав; отдельно проверено отсутствие студентов в текущем предварительном составе на ту же дату.
- Отказ без подтверждения проведения, для пробельной/слишком длинной темы, неизвестной посещаемости и до точного окончания по сохранённому поясу; граница окончания разрешена.
- late сохраняется; исправление и очистка непустой посещаемости требуют причины; непереданная строка остаётся прежней.
- История сохраняет старую тему, автора, UTC и причину; триггеры блокируют изменение/удаление истории, квитанций, исходника и снимка студента.
- Неправильная строка откатывает тему и ранее обработанную строку; искусственный отказ перед commit откатывает весь факт, состав, историю и квитанцию.
- Совпадающий повтор возвращает квитанцию, другое тело конфликтует; старая ревизия и изменившийся после открытия справочник не перезаписывают данные; конкурентные команды дают одного победителя.
- Четыре непреподавательские роли не записывают факт; чтение утверждающего разрешено, admin/student/scheduler не получают содержимое занятия; другая область отклоняется.
- Отозванное назначение запрещает чтение, запись и повтор прежней квитанции. Отдельный конкурентный тест фиксирует отзыв, пока команда ждёт Scope, и получает отказ после освобождения блокировки.
- Черновик не является публикацией; неподтверждённая ссылка нагрузки, архивный источник без факта, дубликаты строк, лишние поля, превышение 100 строк/128 КиБ и неверные Origin/CSRF отклоняются.
- Новая публикация требует сопоставления; связь с существующим фактом сохраняет исходную дату и посещаемость; решение «новое» разрешает отдельный факт. Администратор не получает тему/посещаемость через проекцию состава.
- Исключение из состава сохраняет прежнюю посещаемость, но запрещает дальнейшую запись в неактивную строку. Баллы здесь ещё не проверяются.
