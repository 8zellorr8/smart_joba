## Серверные проверки

`backend/tests/test_journal_grades.py` использует действующие синтетические фикстуры J1.2 и настоящий PostgreSQL. HTTP не подменяется моками.

- 0, 100 и 75 сохраняются/читаются как integer; пустое значение остаётся NULL; посещаемость не выводится из балла, absent не создаёт 0.
- -1, 101, 75.5, boolean, строка, пустая строка и JSON float 0.0 получают 422 без факта, истории и квитанции. Доменная проверка также запрещает неявное приведение.
- Изменение/очистка 0 без причины отклоняются; цепочка 0 → 75 → NULL сохраняет автора, UTC, причину и все прежние значения. Заполнение NULL нулём разрешено без причины. Текущая строка пары студент/занятие остаётся одна.
- Ошибка чужой строки откатывает другую оценку, тему, посещаемость и ревизию; искусственный отказ записи аудита также откатывает транзакцию.
- Admin, approver, scheduler и student получают 403 при прямой команде оценки; только approver из этих ролей читает факт. Административная проекция состава не содержит grade, история фактов ей недоступна.
- Повтор возвращает квитанцию, другое тело конфликтует, старая ревизия не перезаписывает балл, отзыв назначения запрещает даже повтор прежней операции. Две конкурентные правки одной ревизии дают одного победителя.
- Отпечаток пустого grades совпадает с прежним J1.2, повтор с отсутствующим/пустым массивом даёт одну квитанцию без изменения её хранения.
- Дубликаты, >100 элементов, >100 разных студентов суммарно в двух массивах, лишний final_grade, неверные Origin/CSRF отклоняются.
- CHECK отклоняет выход за диапазон; триггеры запрещают изменение членства и изменение/удаление истории.

В `test_journal_lessons.py` усилены прежние сценарии: удалённая из активного состава строка сохраняет 75 и запрещает новую запись/очистку; новая публикация с сопоставлением сохраняет 100, источник и весь состав. Прежняя проверка отсутствия выдуманной оценки теперь проверяет именно NULL, а не отсутствие поля в модели.

## Интерфейс и роли

`JournalLessonsPanel.test.tsx`: 21 тест, включая 9 новых сценариев баллов. Проверены числовые 0/100, пустая ячейка, неверный текст без потери ввода, связанная и сфокусированная сводка ошибок, очистка 0 после отказа причины, только изменённые строки, история 0 → отсутствие оценки, старые JSON без grade, read-only и неактивная строка. Существующие тесты сети и stale усилены значениями баллов.

`frontend/e2e/journal-grades-smoke.mjs` работает только с loopback и существующим явно синтетическим журналом. Пройдены ввод 0/100, неизменённая третья пустая ячейка, отказ 75.5, причины изменения/очистки, последняя запись истории, клавиатурное сохранение, перезагрузка, запреты четырёх других ролей и чтение утверждающего. Профиль студента проверяется успешным ответом `/journal/me` и отсутствием ID остальных студентов; это ещё не кабинет результатов. Два ожидаемых отказа валидации относятся к проверкам, а не к неожиданным ошибкам консоли.

Ширины 320, 360, 857, 1440 CSS px: страница не выходит по горизонтали, таблица прокручивается отдельно. На 360 px Tab переводит фокус на оценку внутри видимой области; оценка и причина введены и сохранены клавиатурой. Имя студента повторяется у поля балла на мобильном экране. Просмотрены финальные teacher-desktop/mobile и approver-desktop. Данные и снимки — приватная `.local/qa/journal-grades/`, в Git не входят.

Полный экранный диктор, 200% масштаб, производительная нагрузка и установка на другой компьютер здесь не проверялись. Целочисленность и одна оценка на занятие остаются предположениями QJ-001/006. Нет выдуманной формулы итогов.
