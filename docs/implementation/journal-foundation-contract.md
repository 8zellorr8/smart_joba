# J1.1 — основа электронного журнала

Дата: 29.10.2026. Основание: ТЗ v1.0, разделы 3–4, 9–11; продолжение после дизайна портала по запросу пользователя «далее». Расписание остаётся нормативно связано с v0.9.

## Граница поставки

Реализованы карточки студентов, интервалы групп, подтверждённая связь аккаунта со студентом, создание журнала по подтверждённой нагрузке и назначения преподавателей. Есть административные KK-формы, просмотр предварительного состава по дате и собственный учебный профиль студента.

Записи проведённых занятий, снимок их состава, темы, посещаемость, оценки 0–100, личные результаты и сопоставление сменившихся публикаций ещё не реализованы. Просмотр состава возвращает `is_snapshot: false`; он не является проведением занятия. XLSX не входит в этот шаг.

Соответствие постановке: JRN-DAT-001–004, подготовительная часть JRN-SEC/OPS и сохранение JRN-BAS. Оценка готовности отдельных AC находится в `journal-foundation-acceptance.json`; статус всего J1 не изменён на «готов».

## Данные

| Таблица | Назначение |
| --- | --- |
| `students` | Постоянный ID, область, имя, `college` / `synthetic`; одинаковые имена допустимы |
| `student_memberships` | Студент, контекст учебного года, группа, интервал `[start,end)`, основание и автор подтверждения |
| `student_account_bindings` | Один student_id на аккаунт в области и один аккаунт на student_id; null отзывает связь |
| `journals` | Уникальная комбинация контекста, группы, subject_id и семестра |
| `journal_assignments` | Преподаватель, журнал, интервал, признак действующего назначения и основание |
| `journal_registries` | Общая ревизия справочника области |
| `journal_setup_changes` | Неизменяемая история команды: автор, UTC-время, до/после, причина |
| `journal_setup_operations` | Неизменяемые квитанции повторов команд |

Миграция `0007_journal_setup` добавляет восемь таблиц. Имеющиеся публикации, версии, группы, нагрузки и календари не переписываются. Отдельная явная команда согласования группы меняет только `RoleGrant.group_id`. Ревизии импорта и расписания от редактирования справочника журнала не меняются.

Интервалы одного студента в одном контексте не пересекаются — предположение QJ-002 из ТЗ. Начальная дата включена, конечная исключена. Перевод: закрыть прежний интервал и добавить следующий; физическое удаление составов не предоставлено. Исправление интервала и имени сохраняет ID и требует причины. Снимки будущих проведённых занятий должны храниться отдельно, согласно JRN-DAT-005/006.

## Серверные права

| Действие | admin | scheduler | approver | teacher | student |
| --- | --- | --- | --- | --- | --- |
| Справочник и история его изменений | Область | Нет | Нет | Нет | Нет |
| Создать/исправить карточку, состав, связь, назначение | Область | Нет | Нет | Нет | Нет |
| Список журналов | Нет | Нет | Область | Подтверждённые назначения | Нет |
| Предварительный состав на дату | Нет | Нет | Область | Только в интервале действующего назначения | Нет |
| Собственный учебный профиль | Только при отдельной роли student и связи | Аналогично | Аналогично | Аналогично | Подтверждённый student_id |

Роль admin не даёт обхода прав чтения журнала. Дополнительная роль teacher сохраняет ограничения назначения. Утверждающий получает чтение согласно предположению QJ-004. Прежние права расписания сохранены.

Все ссылки проверяются по ID, области и data_kind. Имена и email служат подписями выбора, а не автоматическим установлением связи. При связывании аккаунт должен быть действующим и иметь роль student в этой области; его текущая группа должна иметь тот же data_kind. Связывание не меняет роль и группу расписания.

Персональный endpoint не принимает student_id как селектор: идентичность определяется текущей сессией и подтверждённой связью. Он возвращает только имя и собственные интервалы; нет одногруппников, чужих оценок, email, служебных оснований и истории.

## HTTP-контракт

Базовый путь: `/api/scopes/{scope_id}/journal`. Для каждой команды обязательны текущая сессия, разрешённый Origin и CSRF; тело до 128 КиБ. Неизвестные поля POST и нестрогие значения ревизии/логических полей отклоняются.

| Метод и окончание пути | Ответ / действие |
| --- | --- |
| GET `/setup` | Ревизия, студенты, составы, связи, подготовленные аккаунты, контексты, группы, преподаватели, подтверждённые нагрузки, журналы и назначения; только admin |
| POST `/commands` | Команда с `operation_id`, `expected_revision` и типизированным `command`; квитанция `{id, revision, kind}` |
| GET `/history?before_revision=N` | До 50 записей истории и курсор следующей страницы; только admin |
| GET `/journals` | Разрешённые журналы без приватных оснований и аккаунтов |
| GET `/journals/{id}/roster?on=YYYY-MM-DD` | Предварительный состав на дату; повторная проверка назначения преподавателя |
| GET `/me` | Собственная подтверждённая карточка и интервалы групп |

`command.kind` определяет единственное действие:

| kind | Поля кроме kind | Условия |
| --- | --- | --- |
| `create_student` | display_name, data_kind | Непустое имя до 160 символов; новый стабильный ID |
| `rename_student` | student_id, display_name, reason | ID сохраняется; причина обязательна |
| `save_membership` | id/null, student_id, context_id, group_id, start, end, source, confirmed, reason | Область/вид совпадают; нет пересечения; существующий интервал остаётся у прежнего student_id/context_id |
| `bind_account` | user_id, student_id/null, source, confirmed, reason | Отдельное подтверждение; уникальная связь; исправление/отзыв с причиной |
| `sync_schedule_group` | membership_id, reason | Интервал действует сегодня по подтверждённому поясу календаря; уже есть персональная связь; текущая группа роли изменяется явно |
| `create_journal` | demand_id, source, confirmed, reason | Подтверждённая нагрузка без открытых вопросов; группу/предмет/семестр сервер берёт по её ID |
| `save_assignment` | id/null, journal_id, teacher_id, start, end, active, source, confirmed, reason | Нет пересечения активных периодов одного преподавателя в одном журнале; исправление/отзыв с причиной |

`source` — непустой текст до 300 символов; `confirmed` должен быть true. Причина изменения — непустой текст до 500 символов. Назначение преподавателя не выводится автоматически из расписания. Журнал не создаётся из строк неподтверждённого предпросмотра S1.

## Транзакции и повторы

1. Порядок блокировок: область → пользователь/сессия/его назначения ролей → реестр → изменяемые связи. Для чтения используются совместные блокировки; писатели справочника сериализуются блокировкой области.
2. После получения блокировок повторно проверяются действующая сессия, активность пользователя и актуальные роли. Строки авторизации удерживаются до конца транзакции; отзыв, совершённый до проверки, приводит к отказу.
3. Квитанция проверяется до expected_revision, но после текущих прав. Ключ: область + автор + operation_id. Отпечаток включает полное исходное тело и область. Совпадающий повтор возвращает прежнюю квитанцию; изменённое тело — 409.
4. Несовпадающая ревизия — 409 `JOURNAL_STALE`. Новая запись, ревизия, история и квитанция фиксируются атомарно. Ошибка откатывает всё. История и квитанции защищены PostgreSQL-триггерами от UPDATE/DELETE.
5. Все будущие писатели этих справочников должны использовать этот порядок. Будущая запись фактов занятия дополнительно проверяет публикацию, назначение и состав согласно ТЗ; данного контракта недостаточно для выставления оценок.

## Интерфейс и работа с ошибками

Администратор: «Бөлімдер» → «Студенттер және журналдар». Четыре вкладки: студенты, составы, связи аккаунтов, журналы/преподаватели. Преподаватель и утверждающий: верхняя вкладка «Журналдар». Студент: «Оқу профилім»; без подтверждённой связи — понятный отказ.

Поля имеют подписи; ошибка объявляется через alert, фокусируется и связывается с полем. При 422 значения сохраняются. При stale сохраняется ввод, запись блокируется до явного обновления. При потере ответа форма блокируется, повтор отправляет исходные operation_id и тело. При 401 нужен вход, при 403 закрытые данные очищаются. Переход/закрытие страницы с несохранённым вводом предупреждает пользователя. Весь справочник загружается для административной области; массовые реестры и импорт студентов этим шагом не добавлены.

## Следующая функциональная задача

Открытие занятия из точного действующего опубликованного события, неизменяемый снимок исходника и состава, явное подтверждение проведения, проверка времени окончания и дальнейшее сохранение темы/посещаемости. До этого шага не объявлять журнал оценок, AC-JRN-001 или весь J1 готовыми. Реальные списки и назначения предоставляет и подтверждает колледж.
