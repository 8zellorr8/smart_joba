# J1.2 — проведённые занятия, темы и посещаемость

Дата: 29.10.2026. Основание: продолжение пользователем разработки («далее»), ТЗ v1.0 и завершённая основа J1.1. Расписание и пять ролей сохраняют контракты v0.9.

## Граница поставки

Преподаватель открывает журнал → опубликованное занятие → проверяет состав → вводит тему и выбранные отметки → подтверждает проведение → сохраняет. Первое сохранение создаёт постоянное занятие, снимок исходника и состава. Обычный просмотр ничего не записывает. Доступны исправления с причиной и история.

Добавлены необходимые для сохранности этих фактов административные действия: исправить зафиксированный состав; решить, является ли событие новой публикации новым занятием или ссылкой на существующее. Эти действия предусмотрены JRN-DAT-006 и JRN-INT-003–005. Они не дают администратору доступа к теме и посещаемости.

Оценки 0–100 и личные результаты студента остаются следующим функциональным шагом. Текущий студентский экран — прежний профиль J1.1. Занятия не содержат фиктивных баллов, средних или итогов; весь J1 ещё не завершён. XLSX не входит в работу.

## Соответствие требованиям

Реализация покрывает JRN-DAT-005/006, JRN-LSN-001–004, JRN-TOP-001/002, JRN-ATT-001–004, JRN-INT-001–005 для тем и посещаемости и общие SEC/OPS/UX для этих команд. JRN-LSN-005, BAS/STU/GRD и AC, прямо называющие баллы, не объявляются полностью реализованными до этапа оценок. Все 48 ID требований и 64 AC сохранены в `journal-lessons-acceptance.json` с фактическими статусами.

Рабочие предположения ТЗ: QJ-002 — один состав на дату; QJ-003 — запись после окончания занятия; QJ-004 — чтение утверждающим; QJ-005 — present/absent/late/excused/null. Это не подтверждённые правила колледжа. Демонабор явно синтетический; реальные списки и назначения подтверждает колледж.

## Хранение

Миграция `0008_journal_lessons` добавляет пять таблиц без переписывания прежних данных.

| Таблица | Назначение |
| --- | --- |
| `journal_lessons` | Постоянный ID, journal_id, профиль публикации, неизменяемый исходный снимок, тема, ревизия, автор и время первого сохранения |
| `journal_lesson_students` | Уникальная пара lesson_id/student_id, снимок имени и подтверждённого членства, active и отдельная посещаемость |
| `journal_event_links` | Уникальная пара publication_id/event_id; ссылка на факт либо решение администратора «новое занятие» с временно пустым lesson_id |
| `journal_lesson_changes` | Автор, время, действие, ревизия, до/после, причина; неизменяемая история |
| `journal_lesson_operations` | Неизменяемая квитанция и отпечаток запроса, уникальные по области, автору и operation_id |

Триггеры запрещают удаление фактов, строк состава и связей; изменение исходного снимка, автора/времени первого сохранения и снимка членства также запрещено. История и квитанции не допускают UPDATE/DELETE. Связь с фактом после заполнения не переназначается; разрешён только переход подтверждённой новой связи из null в созданный ID. Исправление состава меняет active, сохраняя посещаемость выбывшего студента; возвращение использует тот же ID и прежнюю запись. Новый участник требует подтверждённого членства на исходную дату занятия.

Время хранится как PostgreSQL timestamptz; HTTP-история выдаёт UTC, интерфейс отображает её в сохранённом поясе занятия. Имя автора в интерфейсе — отображаемое имя аккаунта; неизменяемая история сохраняет его ID. Это не подпись студента или поиск прав по имени.

## Источник и первое сохранение

- Основание — точная пара publication_id/event_id из действующего PublicationHead, той же области, контекста, вида данных, группы, предмета и семестра; отменённые события исключены.
- Для нового факта нагрузка должна оставаться подтверждённой и соответствовать ревизии академических ссылок опубликованного события; изменившаяся/неподтверждённая ссылка даёт контролируемый отказ, а не подбор по названиям. Уже записанный факт использует сохранённый источник и не зависит от последующего импорта.
- Преподавателю нужны текущие роль и teacher_id, активное назначение на журнал и дата внутри `[start,end)`; для первого факта teacher_id также совпадает с опубликованным событием.
- Пояс и календарь берутся из подтверждённого снимка публикации. Проверка окончания переводит точный интервал в UTC с отказом при неоднозначном гражданском времени. До окончания запись запрещена; на границе окончания разрешена.
- Подтверждение проведения — строгое true. Тема — обычный текст, непустой после trim, максимум 2000 символов. Пустой подтверждённый состав блокирует первое сохранение.
- Снимок фиксирует publication_id/event_id, номер и ревизию публикации, дату/время/пояс, контекст, group_id/subject_id/teacher_id, семестр, ссылки и ревизии нагрузки/назначения/календаря. Список студентов фиксируется по исходной дате. Перевод или переименование студента впоследствии его не переписывает.

## Общие правила записи

| Правило | Где действует | Проверка |
| --- | --- | --- |
| Серверные права | Чтение, запись и повтор команды | Авторизация и конкретное назначение проверяются до квитанции; admin/approver/student/scheduler не записывают факт |
| Порядок блокировок | Все методы модуля | Общая advisory-блокировка публикаций в shared-режиме → Scope → User/AuthSession/RoleGrant → справочник → факт; публикационный writer использует exclusive до Scope |
| Согласованность состава и прав | Транзакция факта | Scope блокирует параллельную команду справочника; ожидаемая registry_revision проверяет изменения после открытия формы; auth-строки удерживаются до commit |
| Ревизия | Всё занятие и административные исправления | Несовпадение expected_revision или expected_registry_revision возвращает 409 без перезаписи |
| Атомарность | Тема, все переданные строки, состав/связь, ревизия, история, квитанция | Ошибка любой строки или перед commit откатывает всю команду |
| Идемпотентность | Область + автор + operation_id | После текущих объектных прав, до ревизий; одинаковое полное тело возвращает прежнюю квитанцию, иное тело — 409 |
| Причина | Изменение непустого значения, состава, сопоставления | Непустой текст до 500 символов; заполнение ранее пустой посещаемости не считается исправлением |
| Сессия и запрос | Все POST | Прежние Origin/CSRF, тело до 128 КиБ, строгие ревизии/boolean, запрет неизвестных полей; не более 100 переданных строк |

Общая блокировка публикаций удерживается до завершения чтения/записи; публикация не может смениться между проверкой источника и фиксацией факта. Команды каталога J1.1 по-прежнему используют свой контракт. Публикационный writer, генератор и импорт не переносят и не изменяют факты.

Посещаемость — present «Қатысты», absent «Қатыспады», late «Кешікті», excused «Себепті босатты», null «Белгіленбеген». Непереданные студенты не меняются. Дубликаты student_id и студент вне активного снимка отклоняются. Из absent не создаётся ноль; таблицы баллов ещё нет. Частичный состав не обозначается полностью заполненным.

## Новая публикация и состав

Если у профиля есть факты из другой публикации, несопоставленное новое событие блокируется. Администратор с причиной явно выбирает «новое» или постоянный ID занятия того же журнала (контекст/группа/предмет/семестр). Равенство даты, текста и имени не используется для сопоставления. После решения новое занятие всё равно должен подтвердить преподаватель.

Сопоставление сохраняет исходную дату, тему, состав и посещаемость. Интерфейс показывает изменение плана. Архивный источник разрешён только для уже существующей записи; новые факты из него не создаются. Ранее записанные занятия доступны по текущим правам даже при исчезновении события из плана.

При исправлении состава администратор видит только ID, имена, active, исходную дату и ревизии. Он не получает тему, посещаемость или служебную историю фактов. Причина и прежний состав сохраняются в истории, доступной преподавателю и утверждающему по матрице ТЗ.

## HTTP

База `/api/scopes/{scope_id}/journal`. Публичный endpoint для студента к чужому занятию не добавлен.

| Метод / путь | Назначение |
| --- | --- |
| GET `/journals/{id}/lessons?offset=0&limit=50` | Разрешённые занятия: текущие события без факта и ранее записанные, без повторения уже связанного факта; limit 1–100 |
| GET `/journals/{id}/event?publication_id=…&event_id=…` | Предпросмотр без записи либо прежний постоянный факт |
| GET `/lessons/{id}` | Факт и снимок состава, can_write и состояние источника |
| GET `/lessons/{id}/history?offset=0` | 50 записей истории и next_offset |
| POST `/lesson-commands` | Только teacher: record_lesson или update_lesson |
| GET `/lesson-admin/journals/{id}?recorded_only=true` | Метаданные для сопоставления/выбора существующего занятия; постранично, без фактов |
| GET `/lesson-admin/lessons/{id}/roster` | Текущий снимок состава и допустимые кандидаты; без посещаемости/темы |
| POST `/lesson-admin/commands` | Только admin: resolve_event или correct_roster |

Команда: `{operation_id, expected_revision, expected_registry_revision, command}`. Для нового факта expected_revision=0. record_lesson передаёт журнал, публикацию, событие, topic, conducted и attendance; update_lesson — постоянный lesson_id, изменённую тему либо null, только изменённые строки и reason. Строка посещаемости: `{student_id, value}`. resolve_event — journal_id/publication_id/event_id, lesson_id либо null, reason; correct_roster — lesson_id, список активных student_ids и reason. Квитанция: lesson_id/null, revision, registry_revision, kind.

## UX

Преподаватель/утверждающий: «Журналдар» → «Сабақтарды ашу» → «Сабақты ашу». Прежний предварительный состав остаётся отдельным действием. Admin: «Бөлімдер» → «Студенттер және журналдар» → «Сабақтар мен сәйкестік».

Форма различает незаписанный план, сохранённый факт, незаполненную ячейку, ошибку и успех. Сеть/422 сохраняют ввод; 409 блокирует старую форму до явного обновления. При неизвестном результате сохранения поля замораживаются и повторяется точное исходное тело/operation_id. Ошибка дополнительного чтения после подтверждённой квитанции не выдаётся за неизвестный исход записи. 403 очищает закрытые данные; 401 требует входа. Переход с изменениями предупреждает, задержавшийся ответ прежнего выбора отбрасывается. Есть подписи, видимый фокус, alert с переводом фокуса и подписанная прокручиваемая область таблицы.

## Следующий шаг

Баллы 0–100, их исправление/очистка с историей, затем собственные результаты студента по stable student_id, включая прошлые группы и исключённые из текущего состава строки. Только после проверки этих сценариев можно закрывать AC с баллами и весь J1.
