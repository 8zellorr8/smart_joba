# J1.3 — оценки 0–100, исправления и история

Дата: 29.10.2026. Основание: явный запрос пользователя на следующий этап по ТЗ v1.0. База — J1.2 (`f31dd79`); расписание, роли, темы и посещаемость сохраняются.

## Что реализовано

В карточке занятия появился столбец «Баға · 0–100»: первое выставление, исправление и очистка оценки. Преподаватель видит только свои разрешённые занятия; утверждающий читает их без редактирования. Администратор управляет составом и связями, но не получает оценки, тему, посещаемость или служебную историю фактов. Студент и составитель не получают журнал группы через эти методы.

Подтверждён диапазон 0–100. Целочисленность QJ-001 и одна текущая оценка на пару студент/занятие QJ-006 остаются рабочими предположениями ТЗ, а не установленными фактами колледжа. Средний/итоговый балл, перевод в другую шкалу и правила зачёта не вычисляются. Кабинет собственных результатов студента — следующий отдельный этап; текущий профиль J1.1 сохранён. XLSX в задачу не входит.

## Требования и данные

JRN-GRD-001–005 реализованы; JRN-GRD-006 соблюдается в текущем журнале. Расширены проверки JRN-LSN-005, DAT-006, ATT-003, INT-001/005, SEC-001/003–005, OPS-002–004, UX-001–003 на значения баллов. Полная карта всех 48 требований и 64 AC — `journal-grades-acceptance.json`. ТЗ v0.9/v1.0 не переписаны.

`0009_journal_grades` добавляет nullable INTEGER `grade` в существующую `journal_lesson_students`. Существующий составной PK `(lesson_id, student_id)` обеспечивает единственное текущее значение. CHECK допускает только диапазон 0–100 или NULL. Прежние строки получают NULL, не ноль. Исторические JSON и квитанции не переписываются.

Триггер строки состава заменён специализированной функцией: изменяемы только attendance, grade и active; ID, имя, членство остаются неизменяемыми, DELETE запрещён. Прежние защиты урока, источника, связи, истории и квитанций сохранены. Downgrade разрешён до появления данных/истории новой схемы и блокируется после их появления, в том числе после очистки балла; безопасный путь возврата — проверенная копия.

## Контракт команд

Новые endpoint не создаются. В существующих POST `/api/scopes/{scope_id}/journal/lesson-commands` обе команды `record_lesson` и `update_lesson` принимают дополнительный массив `grades`: `[{student_id, value}]`, где value — JSON integer 0–100 или null. Отсутствующий или пустой массив означает «оценки не менять», строка с null — явную очистку именно этой оценки. Числовой 0 сохраняется как 0; строки, boolean, дроби, отрицательные и >100 отклоняются, без округления и преобразования.

Первое сохранение допускает тему, посещаемость и оценки одной командой, но по-прежнему требует действующей публикации, подтверждения проведения, окончания занятия, назначения преподавателя и подтверждённого состава. Для существующей записи действуют её неизменяемый источник и состав.

Передаются только изменённые строки; студент должен быть активен в зафиксированном составе. Непереданная строка не меняется. Повтор student_id внутри одного массива отклоняется. Лимит — 100 разных изменённых студентов суммарно по attendance и grades; изменение двух полей одного студента считается одной строкой. Сохраняется лимит тела 128 КиБ и запрет неизвестных полей.

Изменение/очистка любого ранее непустого балла, включая 0, требует непустой причины до 500 символов. Первое заполнение NULL причины не требует. Посещаемость и оценка независимы: absent не создаёт 0, введённый балл не создаёт present.

## Общие гарантии

Правила J1.2 из `journal-lessons-contract.md` применяются к оценкам без отдельной транзакции: shared advisory публикации → Scope → пользователь/сессия/роли → каталог → факт; текущие объектные права до квитанции; ревизии после квитанции. Одна ревизия относится ко всему занятию. Старый редактор оценки не перезаписывает новую тему или посещаемость. Любая ошибочная строка откатывает тему, посещаемость, баллы, ревизию, историю и квитанцию вместе.

Для совместимости с квитанциями J1.2 пустой `grades` исключается из канонического отпечатка команды: отсутствие массива и `[]` равнозначны. Непустой массив входит в отпечаток целиком. Совпадающий повтор возвращает прежний результат после текущих прав; другое тело конфликтует. Старые квитанции не мигрируют и не изменяются.

Общая неизменяемая история хранит автора, UTC, причину, до/после и ревизию. В новом снимке присутствует grade; в старом ключ может отсутствовать. Интерфейс трактует отсутствие старого ключа как отсутствие оценки, без выдуманного нуля или фиктивного исправления.

Исключение студента из состава запрещает новые записи в строку и сохраняет балл для истории. Новая публикация/сопоставление не меняют его значение или исходник. Личный доступ выбывшего студента предстоит проверить при реализации его кабинета — текущий этап не закрывает AC-JRN-038.

## Интерфейс

«Журналдар» → «Сабақтарды ашу» → «Сабақты ашу». Поля имеют подписи с именем студента; незаполненная ячейка обозначена «Бағаланбаған», ноль виден цифрой. На мобильном имя повторяется рядом с оценкой, чтобы горизонтальная прокрутка не скрывала, кому ставится балл.

Для сохранения ошибочного ввода без преобразований используется текстовое поле с numeric-клавиатурой: десятичное `75.5`, отрицательное и прочий неверный текст остаются видимыми и получают отказ. Это предотвращает очистку ошибочного числового ввода браузером и последующее сохранение его как NULL. Короткая ошибка появляется после выхода из поля; под неё оставлено место. Сводка с ссылками на поля появляется после неуспешной отправки и получает фокус. Валидация на сервере обязательна независимо от клиентской.

Сеть/422 сохраняют ввод. Неизвестный исход замораживает форму и повторяет ту же команду; 409 блокирует сохранение до явного обновления. Известная успешная квитанция не становится «неизвестной» при сбое последующего чтения. 401/403 используют прежнее поведение. Очистка — удалить содержимое поля, заполнить причину, сохранить; прежний балл остаётся в «Түзетулер тарихы».
