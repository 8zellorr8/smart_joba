# Учебный портал: дизайн и навигация

Дата: 27.10.2026. Основание: пользователь выбрал первым шагом дизайн и навигацию
в духе Moodle; электронный журнал остаётся следующим функциональным этапом.

## Что сделано

- Светлая общая шапка, основная навигация «Басты бет», «Пәндер» / «Менің пәндерім»,
  «Сабақ кестесі», имя и роль действующего аккаунта, выход.
- Меню сотрудников «Бөлімдер» в нативном модальном диалоге: прежние разделы
  импорта, календаря, редактора, генератора, согласования и публикаций.
  Доступность пунктов определяется прежними разрешениями из workspace API.
- На главной — карточки предметов из опубликованного расписания, повестка дня,
  существующий проект и действия сотрудника. Студент и преподаватель не получают
  меню составителя или запросы черновиков.
- Страница предметов: поиск по названию, группе и преподавателю, сведения
  о занятиях предмета, переход к точной опубликованной версии и дате недели.
- Компактная шапка на телефоне, локальные шрифт Inter и значки Phosphor,
  оформление входа и казахские подписи учебного портала.

Это представление опубликованных занятий. Карточки не создают курсы, зачисления,
темы, оценки, посещаемость, задания, материалы или проценты освоения. Moodle
на сервер не устанавливался. Модели, миграции, API, роли и данные расписания прежние.
ТЗ v0.9 и постановка электронного журнала v1.0 не изменены.

## Как устроена загрузка

`portal/subjects.ts` использует существующие `publicationApi.list/get` и
`collectWeek`. Сначала сервер ограничивает занятия правами аккаунта, затем
интерфейс собирает все страницы текущих публикаций и группирует доступные
занятия по названию предмета внутри публикации. Название не используется как
идентификатор прав или ресурса. Число занятий считается из полученных записей,
а не из общего `event_count` или списка групп в сводке публикации.

Частичная выборка, смешанные редакции, изменение текущей публикации,
отказ одной из страниц и ошибка доступа дают ошибку с повторной загрузкой.
Они не показываются как успешный пустой список. Предыдущий результат скрывается
при смене набора разрешений, области или снимка. Поздний ответ отменённого
чтения игнорируется. При 401 используется прежний выход через обновление сеанса.
Компонент рабочего пространства привязан к ID аккаунта, области и подтверждённым
сервером связям ролей с преподавателем/группой; изменение связи при повторной
проверке сеанса сбрасывает прежние страницы и данные читателя.

Переход из предмета передаёт ID публикации и дату занятия. Идентификатор группы
не восстанавливается из её названия. Опубликованное расписание остаётся только
для чтения. Кнопки сохранения журнала и другие ещё не реализованные действия
не добавлены.

Backend выдал прежнее предупреждение Starlette о переименовании тестовой
зависимости `httpx` в `httpx2`; проверки прошли. Зависимости в этой задаче
не обновлялись.

Браузерный сценарий проверил вход и выход всех пяти ролей, соответствие карточек
разрешённым сервером занятиям, поиск и отсутствие результатов, чтение предмета,
дату перехода в неделю, фильтры и список расписания, просмотр занятия,
неизменяемость публикации, прежнюю форму редактора без сохранения, отказ сервера
читателю в доступе к черновикам и переходы к прежним модулям.

Для диалога проверены нативная модальность, обход Tab/Shift+Tab, Escape,
кнопка закрытия, возврат фокуса и его переход к основному содержимому после
выбора раздела. Chromium может переводить фокус на документ на границе
клавиатурного цикла; фоновые элементы при открытом диалоге фокус не получили.

Снимки и машинный отчёт закрыты в `.local/qa/learning-portal/`.
Визуальная проверка и её границы описаны в [design-qa.md](../../design-qa.md).

## Как проверить вручную

1. Открыть `http://127.0.0.1:8000/` и войти прежним подготовленным аккаунтом.
2. На главной открыть карточку предмета или верхний раздел «Пәндер» /
   «Менің пәндерім». Проверить поиск и список занятий предмета.
3. Нажать «Кестеде қарау» у занятия: открывается опубликованная неделя его даты.
4. Сотруднику открыть «Бөлімдер» и выбрать нужный прежний инструмент расписания.
5. Преподавателю или студенту проверить, что показаны только разрешённые занятия.

Демонстрационные карточки относятся к синтетической публикации. Исходные файлы
колледжа, базы, пароли и приватные снимки не входят в изменения репозитория.

## Повторение проверок

```powershell
cd frontend
npm test
npm run format:check
npm run build
node e2e/agenda-weekly-smoke.mjs
```

Для браузерной проверки нужны уже установленные Playwright/Chromium и локальные
подготовленные аккаунты. Можно задать `PLAYWRIGHT_MODULE` и
`PLAYWRIGHT_CHROMIUM_EXECUTABLE`; сам сценарий ничего не скачивает. Он допускает
только localhost/127.0.0.1, сохраняет результаты в игнорируемой `.local` и
не отправляет формы изменения расписания.
